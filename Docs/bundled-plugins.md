# 随包分发的插件与版本校正

`example-plugins-v2/` 里那批示例插件会**跟着安装包一起发出去**，而用户数据目录
（`<笔记目录>/plugins/`）里的是**上一次安装时拷进去**的副本。两者会随着版本前进而分叉：
用户手里的那份是老的，新装的宿主却换了。版本校正就是每次启动时把这件事抹平。

## 它做什么

应用启动时（`src-tauri/src/lib.rs` 的 `.setup`，早于前端任何 `plugins_list`）跑一遍
`plugins::sync`：

1. 逐个看随包分发的插件；
2. 数据目录里**没有**这个插件 → 跳过。**不替用户新增** —— 自动装一批插件会突然改变
   开箱界面，那是另一个决定；
3. **有** → 比版本。内置的不比已装的更新 → 一个字节都不改，只顺手记下各文件的哈希；
4. 内置的更新 → 逐文件判断，只覆盖**没被用户改过**的那些。

结果存进内存，由前端启动时调 `plugins_sync_report` 取走（**取过即清空**）。没有值得
说的就完全安静；更新过才弹一条提示。

## 三条硬规矩

改这块之前先把这三条读一遍，它们都是踩出来的：

### 1. 只碰清单点名的文件

`sync::code_files` 只认 `plugin.json` 与清单里的 `main`。**绝不要改成「同步整个插件目录」**：

* `css-modifier/styles/` 是**专门给用户放样式表**的目录；
* `font-pack/fonts/` 是给用户丢字体的。

一次「顺手全同步」就能把用户攒了半天的东西删干净。

### 2. 用户改过的文件一个字都不动

判据是 `plugins-state.json` 里每个条目的 `installedFiles`（相对路径 → SHA-256）：

| 状态 | 处理 |
|---|---|
| 记过账、且磁盘上那份哈希仍等于账上的 | 用户没动过 → 覆盖 |
| 记过账、哈希对不上 | **用户改过 → 跳过**，日志记「本地有改动」 |
| 没记过账（老版本装的插件都是这样） | 判断不了 → **先把原件备份**，再覆盖 |

第三行就是 `.backup/` 存在的理由：判断不了的时候，宁可多留一份也不要赌。

记账记的是**内置文件**的哈希，不是磁盘上那份的。这个区别很关键：拿磁盘上那份的哈希去
记账，等于把用户改过的内容封成「原样」，下次升级就会心安理得地把它覆盖掉。所以内容与
内置的不一致时**干脆不记账**，留给下次走备份那条路。

### 3. 版本号比不了就不更新

`version` 在清单里是自由字符串（缺省是空），所以 `version_is_newer` 只在两边都拆得出
数字段时才可能返回 `true`，**拆不出来一律判「不更新」**。反过来写的话，一个写歪的版本号
就能把用户的插件冲掉。

## 加一个随包分发的插件

1. 插件目录照常放进 `example-plugins-v2/<名字>/`；
2. 在 `plugin.json` 里把 `version` 写清楚 —— 校正全靠它判断新旧，留空就永远不会被更新；
3. 完事。`tauri.conf.json` 的 `bundle.resources` 是整个目录一起拷的，不用逐项登记。

想放**用户自由编辑**的文件（样式表、字体、模板），就放进插件目录里的子目录，然后在
`code_files` 之外 —— 校正不会碰它们。

## 状态文件迁移

`plugins-state.json` 里的 `version` 字段从初版起就写着，但一直没人读。现在
`state::load` 会在读到低版本时就地升级并写回（`migrate`），低版本文件的启停与授权原样保留。

将来真要改字段含义，**在 `migrate` 里逐级加分支**，别直接跳到最新版：一个从 1 升上来的
文件得依次跑过 1→2、2→3 每一步。

## 调试

* 日志前缀 `[plugins:sync]`，只在该应用的 debug 构建里输出（`sync_log!`）；
* 隔离实例（`npm run dev:isolated`）的内置源在 `src-tauri/target/debug/example-plugins-v2/`
  —— 那是构建脚本从仓库拷过去的，直接改它不会被下一次构建覆盖，只受影响于仓库源；
* 想看更新效果：把 `src-tauri/target/debug/example-plugins-v2/<名字>/plugin.json` 的版本
  调高，重启隔离实例即可。
