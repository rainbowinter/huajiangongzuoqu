# PDF 批注插件（`example-plugins-v2/pdf-annotations/`）

给 PDF 圈画、划重点、钉批注。**它不注册文件类型** —— 它用
[`api.files.extendView`](./plugin-api.md#扩展别人的视图apifilesextendview) 把自己并进
[`pdf-viewer`](./pdf-viewer.md) 那个视图里，顺带证明了一件本来只是设想的事：
**两个插件的代码可以共用一个沙箱帧**（各包一层 IIFE，靠 `globalThis.floralPdfView` 说话）。

```json
{
  "requires": ["pdf-viewer"],
  "permissions": ["files:view", "workspace:cache", "ui:document-action"]
}
```

## 这一层是怎么叠上去的

pdf-viewer 的视图里，一页是这样一个盒子：

```text
<.page>
  <canvas>        画出来的 PDF
  <.textLayer>    透明的文字（可选中、可搜索，z-index 1）
  <.anno-layer>   ← 批注层（z-index 2）
```

`z-index` 是**必须**的，不能靠 DOM 顺序：文字层是异步画的，有可能在批注层之后才追加。
批注层自己 `pointer-events: none` —— 那样文字才选得中、拖拽也才落得到页面上；
**只有「指针」模式下标注自己接管点击**（点一下选中它）。

## 坐标一律存 PDF 的用户空间

这是整个插件里唯一真正要小心的地方。

屏幕坐标（页内像素）**会随缩放与旋转变化**：同一块高亮，100% 时在一处、200% 时在另一处，
转 90° 之后完全对不上。所以落盘的每一处几何都过一遍
`PageViewport.convertToPdfPoint`，显示时再用 `convertToViewportPoint` 换回来 ——
两个方向都由 pdf-viewer 通过 `globalThis.floralPdfView` 交出来：

```js
pdf.toPdf(页号, x, y); // 页内像素 → PDF 用户空间（存这个）
pdf.toPage(页号, x, y); // 反过来（画的时候用）
pdf.onPages((pages) => { ... }); // 页面（重新）建好了 —— 缩放、旋转、翻页都会来一次
```

实测过的往返：在 103% 下画一个 (80,120) 240×70 的框 → 转 90°（此时是 80%）变成
(486,62) 54×185（宽高换了个个儿，尺寸乘 0.8/1.03）→ 转回来仍在 (80,120) 240×70。

⚠️ 顺带一个坑：**自由笔的线宽也得这么算**。`toPage(72, 0)` 量的是「72 个 PDF 点在这个
缩放下有多长」，除以 72 才是「1 个点 = 几像素」。而且必须取**两点距离**（`Math.hypot`），
不能只看横坐标之差 —— 页面转 90° 时那个位移整个落到 y 上，只看 `[0]` 会得到 0，
线细成一根头发。

## 五种标注

| 工具 | 交互 | 存的是什么 |
|---|---|---|
| 指针 | 点一下选中（见下），`Delete` / `Backspace` 删掉 | —— |
| 矩形 / 圆形 | 按住拖一个框 | 一对角点的 PDF 坐标 |
| 自由笔 | 按住随便画 | 折线点列（取点间隔 2.5px，太密数据会白胖几十倍） |
| 文字选区 | 像在网页上那样划过去选中文字 | **每一行盒**一对角点，所以高亮贴着字走、不会圈住整块空白 |
| 图钉批注 | 点一下，弹框写字，回车保存 | 一个点 + 文字；移上去或选中就看得到内容（下详） |

颜色是四个色块（黄 / 绿 / 蓝 / 粉），高亮带透明度 —— 盖死了就没法读了。

### 选中与删除：一套约定

这是从这一版起定下来的**插件自己的方式**，四种标注一视同仁：

1. **点一下选中**（指针模式）。选中的那一圈是**实心描边 + 外发光**，比悬停那圈细线明显得多
   —— 「删除键删的是谁」必须一眼看得出来。
2. **`Delete` / `Backspace` 删掉选中的那条。** 点空白处或按 `Escape` 取消选中。
3. ⚠️ **在写字框里按键时一律不管。** 不判的话「在输入框里按退格改错字」会变成「把选中的
   那条标注删了」—— 打错一个字、想删掉它，结果批注没了，还查不出是谁删的。

**为什么把那个 × 去掉了**（原来悬停时右上角冒一个红叉）：它只挂在悬停才出现的一小块上，
触屏按不到；而且**多矩形标注（文字选区）每一行都会冒出一个 ×**，看着像有十来个能删的东西，
点哪个其实都删整条。改成「选中 + 删除键」之后，选中的是哪一条在屏幕上写得清清楚楚。

自由笔另有两处特殊：

- **它的命中层是一条透明的粗线**（`.anno-ink-hit`，12px）。整张 `.anno-ink` svg 铺满一页，
  要是让它吃事件，整页文字就都选不中了 —— 所以 svg 保持 `pointer-events: none`，只给那条
  透明粗线 `pointer-events: stroke`（**不要求看得见**，透明描边照样接得到点击）。真正画出来
  的那条线只有一两像素宽，光靠它按不准。
- **它没有「框」**，选中时照笔迹算一个包围盒画虚线（比笔迹四周各大 3px），否则看不出选没选中。

### 图钉那颗黄点

屏幕上只有一颗 18px 的黄点（Acrobat 的便签也是这个路子：**正文里不占地方**）。批注文字
平时是藏着的，两条路能看：

- **移上去**（指针模式下）—— 路过看一眼；
- **选中**（点一下）—— **钉住**。想一边读批注一边选正文、滚页面、双击改字，都得用这个，
  触屏上更是只有这条路。

**展开的样子是一张跟着图钉颜色走的圆角小卡片**，从那个点「长」出来：

```text
悬停 / 选中 →  ⊙          变成         ┌─────────────┐
              （圆点）                  │ 这里要再看看 │  ← 底色就是这颗图钉的颜色
                                        └─────────────┘
```

- **不做「一个元素变宽变高」**：卡片是 `width: max-content`（原因见下），而 `max-content`
  **不可动画** —— 硬过渡只会在中途跳一下。改成「圆点缩小淡出 + 卡片从同一个原点放大淡入」，
  看上去就是那个点长成了卡片，两边都能顺滑过渡。
- **`transform-origin` 要挪到图钉那个点上**：卡片相对 wrap 原点在 `(14, 10)`，所以写
  `transform-origin: -14px -10px`。不写的话是从卡片**自己**的左上角放大，看着像从旁边的
  空气里冒出来。
- **展开后要 `pointer-events: auto`**：平时是 `none`（否则它会挡住底下的文字），但**双击
  改文字**就落在它身上，展开时必须收得到事件。

**双击卡片 = 就地改那段文字**（编辑框开在图钉原地、也接上那颗图钉的颜色，读起来就是
「卡片变成了可以打字的样子」）。矩形 / 圆形 / 自由笔 / 文字选区没有文字内容，双击它们
**什么都不做** —— 免得误触。

⚠️ 图钉这里踩了三个坑，都挺隐蔽：

1. **那个悬浮框的宽度不能不给。** 图钉的定位点是一个 **0×0** 的 wrap，绝对定位元素在不给
   宽度时会去「适应可用空间」—— 可用空间是 0，于是一路收缩到 min-content：**一行一个字**，
   整条批注变成 27px 宽的一竖条。必须 `width: max-content` 量出真实文字宽度，再让
   `max-width` 去截。
2. **悬停规则要挂在 wrap 上，别细化到子元素。** 原来写的是
   `…… .anno-pin-hit:hover + .anno-pin-note`（相邻兄弟），而 wrap 里 hit 与 note 之间还夹着
   那颗圆点，`+` **永远匹配不上** —— 表现就是「图钉只有一个黄点、怎么也不出字」。
3. **事件层是个死元素。** 本来有个专门用来吃事件的 `.anno-pin-hit`，但圆点转 45° 之后
   外接框比它大，**整个把它盖住了**（实测 `elementFromPoint` 在圆点附近取七个点，全落在
   圆点上），所以挂在它身上的 `title` 提示从来弹不出来。现在 `title` 挂在 wrap 上（`title`
   会顺着祖先找），hit 那一层直接删了。

顺带一句：改完这类样式**别用合成事件验悬停** —— `:hover` 只有真指针才触发；而
`getComputedStyle` 读到的是**过渡动画的当前值**，点完马上读只能读到 0。验法是
`document.querySelectorAll('.anno-pin-wrap:hover').length`，它跟着真实悬停状态走。

⚠️ 还有一条改这层代码时的通病：**选中会整层重建**（`renderPage` 是 `layer.replaceChildren()`），
所以拿在手里的那个节点**点一下就失效了**。测试里点完要**重新查一次 DOM**，否则读到的是一串
空的计算样式，看着像「什么都没发生」。（原型里的探针就因为这个误报过两次。）

**选中框用的是视图的强调色** `var(--accent)`，由 pdf-viewer 从宿主的 `--color-bamboo` 映过来
（`viewer.js` 的 `TOKEN_MAP`）—— 所以它会跟着深浅主题走，深浅两套里都是那个绿。

文字选区靠的是 pdf-viewer 的**文字层**（`Docs/pdf-viewer.md` 里那层透明的 span）：
`selection.getRangeAt(i).getClientRects()` 一行一条矩形，逐行换算成 PDF 坐标。
所以这一版**必须**先有文字层，文字层做完「选中 / 搜索」也就顺带能做了。

## 存到哪

`floralView.extension("pdf-annotations")` 给的私有数据通道，落点是
**PDF 旁边**的 `__floral-notepaper__/pdf-annotations/<相对路径>.json`：

```text
E:\笔记\
├── 论文.pdf
└── __floral-notepaper__\pdf-annotations\论文.pdf.json
```

把 PDF 拷到别处、发给别人，标注跟着走；删掉那个文件夹就等于清空批注。机制本身见
[`Docs/workspace-cache.md`](./workspace-cache.md)。

存盘是**防抖**的（停手 400ms 才写）—— 拖拽时每一帧写一次盘太浪费。读回来的数据形状
未必还靠谱（用户手改过、别的版本写的），所以每条标注都要过一遍 `isSaneMark`，
坏的直接不要 —— 一条坏数据不该让整份批注都画不出来。

## 另存为带批注的 PDF

**「导出批注」在主窗口顶上那一行**，不在预览区那排视图小工具里：

```js
api.ui.registerDocumentAction({
  id: "export-pdf",
  title: "导出批注",
  typeIds: ["pdf-viewer:pdf"], // 只在打开 PDF 时出现
  viewCommand: "export-pdf",   // 转发给当前视图帧
});
```

分界线是「**这是对这一份文档做的事，还是对这一屏画面做的事**」—— 翻页、缩放、选标注工具
是后者（`view.toolbar`），导出是前者，和「另存为 PDF」「打印」是一类。机制见
[`Docs/plugin-api.md` 的 `registerDocumentAction`](./plugin-api.md)。

⚠️ 这里必须用 `viewCommand` 而不是 `run()`：**真正的活在帧里**（`view/annotate.js` 的
`exportAnnotatedPdf` 拿得到 pdf-lib、原文件字节和所有标注坐标），而 `index.js` 跑在
**Worker** 里，够不到那些东西。宿主点到时把 `{ t: "command", id: "export-pdf" }` 转给
当前那个视图帧 —— 与 `view.toolbar` 控件收到的是同一条消息，`annotate.js` 里那句判断
原样能用。

它会（或说：你点它之后，帧里的代码会）把标注**写进 PDF 自己的注释对象**，另存成
`原名-批注.pdf` —— **原文件一个字都不动**（用户明确要的）。写出来的是标准注释，
Edge / Acrobat / WPS 打开就是真批注，不再只是花笺的私有数据。

对照表（屏幕上的东西 → PDF 里的注释对象）：

| 屏幕上的 | PDF 注释 | 关键字段 |
|---|---|---|
| 矩形 / 圆形 | `/Square` / `/Circle` | `/Rect`、`/IC` 填充色、`/CA` 透明度 |
| 文字选区 | `/Highlight` | `/QuadPoints`（每行 8 个数，顺序是左上、右上、左下、右下） |
| 自由笔 | `/Ink` | `/InkList`（点列）、`/BS` 线宽 |
| 图钉批注 | `/Text` | `/Contents`（**中文要走 UTF-16 的 HexString**，`PDFString` 只认 latin1） |

都带 `/F 4`：**打印时也要画**。少了它，注释只出现在屏幕上，打出来一片干净 —— 那种
「明明做了批注，打出来什么都没有」最难查。

**坐标直接照搬落盘的那份**：我们存的就是 `convertToPdfPoint` 的未旋转用户空间，注释的
`/Rect` 也是同一个空间（页面自带的 `/Rotate` 由阅读器再套一层）。原型里验过：在视口
(80,120) 画的框，`toPdf` 给出 `[77.3, 676.0]`，导出的 `/Square` 读回来是
`[77.3, 608.3, 309.4, 676]` —— 分毫不差。

**几条实现的坑**：

- **pdf-lib** 是 UMD，拼进内联 module 时走 `self.PDFLib = {}` 那条分支（模块顶层 `this`
  是 `undefined`，`|| self` 兜住）。按 sha256 从 CDN 取，见 `scripts/fetch-pdfjs.mjs`。
- **字节要另要一份**：`document` 消息里的 ArrayBuffer 被 pdf.js 转移给 worker 了，
  直接拿来喂 pdf-lib 会报 `detached ArrayBuffer`。所以导出时调
  `floralView.requestDocumentCopy()`（见 `Docs/plugin-api.md`）。
- 加密的、pdf-lib 读不了的 PDF：**明说**读不了，不写半份出来。
- **这不是同步**：导完再把批注改一改，得重新导出一次。会话里那份 JSON 仍然是应用内
  看到批注的依据。

## 还没做

- **撤销 / 重做**：画错了只能删掉重画。
- **移动已有的标注**：现在只能删。
- **批注列表**：钉了十几个图钉之后，没有一栏把它们列出来。
- **导出**：不能把批注导出成图片或打印。
- **跨页选择**：`commitSelection` 其实按页分了组（跨页选中会分别落在各自的页上），
  但没测过滚动中跨页拖选的边界情况。

## 怎么验它

不用起应用 —— 原型在 `%TEMP%\pdfproto\`：`sync.mjs` 从仓库拷插件真文件（连写死的
`VIEW_PRELUDE` 都从 `viewBridge.ts` 里抽），`proto.html` 自己扮演宿主（读声明、拼 srcdoc、
画工具栏、转发消息）。里面带一个**帧内探针**：沙箱帧是 opaque origin，父页够不着它的 DOM，
所以「在页面上拖一下」「划一段字」这类动作只能由帧里的代码自己合成指针事件来完成。

```bash
cd "$TEMP/pdfproto" && node sync.mjs && node serve.mjs   # http://127.0.0.1:8099/proto.html
```

> 探针会把 `setPointerCapture` 换成空实现 —— 合成事件没有真的 pointer，原生实现会抛
> `NotFoundError` 把处理函数打断。**只有原型里有这一步**，真应用里用户是真的指针。
