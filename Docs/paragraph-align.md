# 段落对齐（居左 / 居中 / 居右）

编辑器工具栏上那三个按钮（⇤ ⇔ ⇥），把**一整段**改成居左、居中或居右。

## 笔记里写的是什么

```text
::: center
这段字居中
:::
```

`::: left` / `::: right` 同理。标记行单独占一行，`::: center` 与 `:::` 之间的内容
就是被对齐的部分，可以有多段。

**为什么不写 HTML。** Markdown 原生没有段落对齐，最直接的做法是往正文里写
`<div align="center">` 或 `<center>` —— 那等于把排版混进了正文：笔记拿到别的编辑器里
就露馅，源码里也一眼看得出是「外挂」的东西。`:::` 是 Markdown 圈已有的容器写法
（VitePress、Docusaurus 都在用），读起来仍然像 Markdown。

## 三条规则

1. **再点一下取消。** 选中一段再点同一种对齐，就是把标记撤掉；点另一种则直接换过去，
   不会先撤再加。
2. **按段而不是按行。** 光标停在哪一行，整段（上下直到空行为止）一起处理 ——
   只包当前一行会把一段劈成两半，上面居中、下面掉回左边。
3. **内容以列表 / 表格 / 引用结尾时，收尾的 `:::` 前面要空一行。**

第 3 条是 Markdown 的「惰性续行」规则在作怪。实测：

```text
::: center
- 甲
- 乙
:::          ← 这行会被并进最后一个列表项里
```

表格更糟，`:::` 会变成**新增的一行数据**。空一行就没事：

```text
::: center
- 甲
- 乙

:::
```

工具栏按钮会**自动判断并补上**那一行，手写时才需要注意。
（围栏代码块、缩进代码块、标题都没有这个问题，实测过。）

## 写了一半怎么办

只有开头没有收尾时，整块按**普通文字**渲染 —— 你能一眼看出自己少写了什么。
宁可显示得难看，也不要默默吃掉正文。

## 代码在哪

| 文件 | 管什么 |
|---|---|
| `src/features/markdown/alignText.ts` | 编辑区那一侧：套 / 换 / 撤标记，纯字符串函数 |
| `src/features/markdown/remarkAlign.ts` | 渲染那一侧：把容器转成一个带类名的 `div` |
| `src/App.css` 的 `.md-align-*` | 实际的 `text-align` |
| `src/features/markdown/scrollSync.ts` | 滚动同步时跳过标记行（预览里它们不占位置） |

两侧共用同一套标记行解析（`alignText.ts` 里的 `parseAlignMarker` / `isAlignClose`），
所以语法永远只有一份定义。

滚动同步那一处不能忘：标记行**只存在于源码里**，预览里一个字都不产生。不把它们排除掉，
源码与预览的行对应关系会一路偏移 —— 而且是滚到后面才发现差了几行的那种偏。
