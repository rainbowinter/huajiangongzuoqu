# 随包的说明文档与「关于」面板

管两件事：右上角**「关于」侧栏**里的四篇说明，以及插件面板里**「详细信息」**生成的插件说明。

## 「关于」为什么是侧栏，不是下拉菜单

它一开始是标题栏上的下拉菜单，**点不动** —— 标题栏那套拖拽/叠层会吃掉点击。改成侧栏之后
两个问题一起解决：点击不用穿过叠层，而且**放得下东西**。现在栏里除了三个文档入口，还有：

- 版本号（`getVersion`）；
- **发布页**（从更新源推出来的，见 `aboutLinks.ts` —— 只留一个事实来源，换仓库时不会
  出现「更新源换了、关于面板还指着老地址」；认不出来就整行不显示，不给半截链接）；
- **更新源**（`update_endpoint` 命令，没配就写「未配置」）；
- 笔记目录（设置里的 `dataDir`）与插件目录（`plugins_dir_path` 命令）。

加一条新信息就在 `AboutPanel.tsx` 里加一个 `Row` —— 它就是个「标签 + 值（可选可点）」。

## 只读文档视图与标签页

正文区多了一种内容来源：**内存里的 Markdown 字符串**。它现在是**标签页的一种**
（`OpenDocument.kind === "doc"`），不再是浮在笔记上的临时视图：

- 标签的 `id` 是文档键（随包文档用文件名，插件 README 用标题），`key` 是 `doc:<id>`；
- **正文存在 `docTabsRef`**（`Map<key, { title, content }>`）。切走再切回来直接从
  内存取，不重新读盘；
- 激活只读文档时先保存当前笔记，再 `clearCurrentNote()`、设 `docView`；
- 它**绕开保存路由** —— 没有路径可写；也**完全不碰 `externalFiles`** —— 那个列表
  同时还是「这个 id 是不是外部文件」的判据；
- 关标签时连同 `docTabsRef` 里的正文一起删掉；关掉最后一个标签回到空状态；
- 标签上画一本书（`FileKindIcon kind="doc"`），与笔记、文件的图标区分开。

挂载点仍在主窗口中央内容区条件链的**最前面**（`docView ? … : standalonePreview ? …`），
标题栏也跟着换；右上角的「关闭」现在等价于关掉这个标签（走 `closeTab`），不会再出现
「视图没了、标签还留着」的半截状态。

## 「关于」的四篇文档

文档本体在仓库的 `Docs/user/` 下，`tauri.conf.json` 的 `bundle.resources` 把它映射成
安装目录里的 `docs/`：

```jsonc
"resources": {
  "../example-plugins-v2": "example-plugins-v2",
  "../Docs/user": "docs"          // ← 与插件走同一条路
}
```

`tauri_build` 会把它拷进 `target/{debug,release}/`，所以**开发时也读得到**（Windows 上
资源目录就是 exe 所在目录）。实测过：`target/debug/docs/` 下四篇都在。

其中 `custom-css.md` 是**自定义样式的完整说明**：变量表、三种主题覆盖、语义钩子清单、
覆盖 Tailwind 的做法，以及一段可以直接抄的完整例子。它原先整段以注释形式写在
`src/styles/custom.css` 里，现在那份模板**出厂是空文件**，说明统一收进这份文档。

### 加一篇说明要动四个地方

1. `Docs/user/<新文件>.md` —— 正文；
2. `src-tauri/src/docs.rs` 的 `ALLOWED_DOCS` —— **不加就读不到**；
3. `src/features/docs/api.ts` 的 `BundledDocName` 联合类型 —— 让两边的白名单一眼能对上；
4. `src/features/docs/catalog.ts` 的 `ABOUT_DOCS` —— 界面上那一项（顺序即显示顺序）。

### 为什么要有白名单

文件名是前端传来的。不加限制的话，一个 `../../../` 就能读到任意文件 —— 而这条命令唯一的
用途就是读固定那几篇。`docs.rs` 里做了两道：白名单 + 只取路径最后一段。两道都不贵，
而这类漏洞的代价很大（单测把各种 `../` 都钉住了）。

## 插件的「详细信息」

点插件面板里那个按钮，把清单里的东西现算成一份 Markdown（`features/docs/pluginDetails.ts`
的 `buildPluginDetails`，**纯函数**）：

- 版本 / 作者 / 主页 / 安装目录；
- 运行状态与沙箱（说人话，不写 `apiVersion`）；
- **声明了哪些权限**（没能拿到的单独标出来）；
- **在界面上加了什么** —— 面板 / 工具栏按钮 / 浮层 / 命令 / 行旁注 / 行内装饰 / 菜单，
  按归属过滤**活的注册表**；
- 可以调的设置项。

两处刻意为之：

- **数据由调用方凑好传进来**，生成器只负责排版。那些数据要从好几个注册表里读，不适合
  放进生成器，也没法在单测里造（单测直接喂构造好的输入，见 `pluginDetails.test.ts`）。
- **每次点都现读一遍注册表**，不缓存 —— 插件被停用后条目会消失，缓存下来的话详情里
  还会写着它加过什么。

## 已知范围

**文档只有中文版。** 界面是 i18n 的，随包文档不是。要补多语言时，`Docs/user/` 的命名
约定、`ALLOWED_DOCS`、`BundledDocName` 三处要一起动（例如按 locale 加分文件名再回落）。

生成出来的插件说明同理，目前也是中文。
