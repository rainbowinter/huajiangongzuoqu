# 颜色块

代码文件里每个颜色字面量前面浮着一个小色块，点它直接开系统取色器，选完把原来的颜色换掉。

## 用它

打开任意一个**代码文件**（`.css` / `.js` / `.py`…），凡是写着颜色的地方，左边就有个小色块：

```css
.title {
  color: #ffd400;              /* ← 这一行前面有一个黄色的小方块 */
  background: rgba(0, 0, 0, .5);
}
```

* **点一下色块** → 弹出系统调色盘，选一个颜色，正文里的那个字面量当场被替换；
* **带透明度的保住透明度**：原来是 `rgba(...)` / `hsla(...)` 的话，换完还是 `rgba(...)`，
  而且 alpha **原样**带回去 —— `.25` 还是 `.25`，`50%` 还是 `50%`。
  （取色器本身只能表达不透明色，直接写 `#rrggbb` 会把半透明黑变成实心黑。）
* **不带透明度的**统一折成六位 `#rrggbb`：`#fff` 会变成 `#ffffff`，
  `hsl(0 0% 0%)` 会变成 `#000000`。

认这三种写法：`#` 十六进制（3 / **4** / 6 / **8** 位都行）、`rgb()` / `rgba()`、`hsl()` / `hsla()`。

**只对代码文件生效**（`.css` / `.js` / `.py`…）。笔记与 Markdown 里出现 `#fff` 多半是正文内容
而不是颜色声明，标上色块只会碍事。

**注释里的颜色不标。** 扫一遍 `App.css` 就知道，注释里满屏都是「曾经的」颜色，
全标上色块既吵又容易点错 —— 所以 `/* … */` 与 `// …` 里的都不算。
（URL 里的 `https://` 不会被当成注释开头。）

## 它要的权限

| 权限 | 为什么 |
|---|---|
| `ui:decorations` | 往正文某个位置叠一个小控件（就是那个色块） |
| `editor:write` | 换色时改写正文 |

色块的位置是**宿主**量的 —— 插件跑在沙箱里，没有 DOM，量不出某个字符在屏幕上落在哪儿。
插件只回答「第几个字符起、多长、什么颜色」，排版归宿主。

## 还没做的

* 不认 CSS 的**命名色**（`tomato`、`rebeccapurple`），也不认 `color()` / `lab()` 这类新写法。
* 只有取色器，没有「最近用过的颜色」。
* 只改颜色本身：想换个写法（`#fff` → `#ffffff`）得自己动手。
